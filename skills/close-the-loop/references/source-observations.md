# 来源观察

本 skill 从本地 ZGent 检出版本 `c4e7448429c65941382184647f312ba70f6d1f6c` 中可观察的工程实践独立提炼而来。它提取可迁移机制，不包含 ZGent 产品指令，也不声称覆盖作者未记录的知识。下列上游位置只用于追溯来源，不是运行时依赖：即使没有 ZGent 检出目录，下面的机制表和证据摘要也必须足以理解并质疑每条规则。

`SKILL.md` 负责可执行协议；本文负责来源、失败机制和有意省略项。修订协议时，确保“失败模式到规则”的映射在两个方向上都保持真实。

## 失败模式到协议规则

| 失败模式 | 机制 | 规则 |
| --- | --- | --- |
| **陈旧地图式实现（Stale-map implementation）** | 遵循旧补丁、工作日志或记忆中的文件布局，比重建当前运行路径更省事；修改可能只在已不存在的架构上局部正确。 | 1 |
| **模糊完成（Vague done）** | 文件清单或绿色构建取代了可观察的完成标准，最困难的负向或恢复属性没有被命名，因此无法阻止交付。 | 2、8 |
| **调用点局部修补（Boundary-local patch）** | 修复可见调用方比寻找状态或契约所有者更省事；其他消费者保留同一不安全路径，缺陷会在另一个入口重现。 | 1、3 |
| **静默降级（Silent degradation）** | 不存在、畸形、拒绝和失败状态都被压成一个默认值；系统通过擦除保护数据或诊断故障所需的信号来维持表面可用。 | 4 |
| **只验证稳态（Steady-state-only verification）** | 测试只观察一次成功调用，而生产故障发生在调用之间：重试、重启、重连、取消、陈旧完成、并发或清理期间。 | 5 |
| **偶然变绿（Incidental green）** | 测试通过是因为宿主策略、时序运气、既有防御或未经断言的前置条件，而不是正在审查的机制。 | 6 |
| **闭环不完整（Incomplete closure）** | 检查一个代表性资源、调用方、重定向、状态副本或目标后，就把它当作完整集合；部分成功看起来像全部完成。 | 3、6 |
| **表演式审查（Review theater）** | 审查重复作者的叙述，只看预期路径，或在没有实质停止条件时围绕细枝末节无限继续。 | 7 |
| **证据膨胀（Proof inflation）** | 聚焦、广泛、人工、目标环境、受阻和未执行检查被混合成一句没有区分的“已验证”。 | 8 |
| **仪式膨胀（Ritual inflation）** | 面向重要工作的协议被统一套用到局部确定性修改；流程消耗注意力，却没有暴露额外失败模式。 | 2、7、8 |
| **边界反例遗漏（Boundary counterexample omission）** | 首轮验证覆盖了显式成功、失败和重启，却没有挑战表示碰撞、特殊资源、悬挂操作或 durable state 与外部效果之间的顺序；宽泛的“已覆盖边界”声明仍可能漏掉实质缺陷。 | 2、5、6、7 |
| **能力域外默许（Capability-domain ambiguity）** | 复制、冻结、解析或迁移只在常见值上成立；遇到不支持的值时静默复用原引用、误分类旧数据，或在部分效果之后才失败。 | 2、3、4、6 |
| **规模正确但不可用（Scale-disproportionate correctness）** | 每条记录都执行同步持久化或全量扫描，功能测试全绿，但在任务明确声明的规模上失去实用性。 | 2、5、6、8 |

## 本地前向评测后的迭代

`0.6.0` 在不改变上述 ZGent 来源归因的前提下，加入了本地盲化前向评测暴露的通用反例类别。评测显示，常规隐藏测试全部通过并不排除以下机制缺口：合法 legacy 值与 envelope 标记碰撞、attempt 已持久化但外部调用尚未发生、悬挂读取使取消被 cleanup 反向阻塞、特殊文件类型在 open 时阻塞、严格文本解码缺失、不可复制值静默复用原引用，以及逐记录同步 I/O 在声明规模上失去比例性。

这些观察只支持新增“如何推翻模型”的诊断问题，不支持把任何评测题的具体实现写成通用答案。因此协议要求按风险选择反例、明确不支持域，并把事后探索与预注册证据分开；它不强制某一种 WAL、schema、clone、文件 API 或批次大小。

## 有意省略

- ZGent 工具名称、工作区路径、RPC 方法、应用 profile、记忆协议和终端指令属于宿主能力，不属于可迁移工程判断。
- 远程 issue、分支、push、merge request 和 pipeline 操作属于交付策略。本 skill 不授权这些操作。
- 不强制使用 workbook。采用项目已有的本地表示即可，只要它能让闭环状态可观察且不会增加无效流程。
- 冷审按风险缩放。本 skill 不要求必须使用 subagent、固定审查者数量，也不要求在实质性发现归零后继续审查。
- `fail closed` 不是通用错误策略。只在宽松回退会暴露授权、隔离、机密性或持久完整性的边界使用它。
- 完整测试套件和人工验证不是通用门禁。它们是根据风险和环境选择、彼此独立的证据类别。
- ZGent 的具体解决方案只是例子，不是强制模式。可迁移经验在于如何定位失败并用证据推翻错误假设。
